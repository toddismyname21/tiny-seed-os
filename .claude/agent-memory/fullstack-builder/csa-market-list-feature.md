The Market List (`/admin/market`) is the farmers-market channel of the unified product catalog (roadmap #2 after [[csa-admin-trust-dashboard]]'s Products master screen). Each week staff pick which `product_library` products are sold at the stall + set retail unit + price.

**Why:** unifies the catalog so one product's photo/identity (from `product_library`) shows across flex, box, wholesale, AND market; market is just another weekly channel.

**How to apply:**
- Table `market_offerings` (`id, library_id NOT NULL → product_library, week_starting date, name text optional override, unit text default 'each', price_cents int, is_active bool, sort_order int, created_at, updated_at`). RLS `market_offerings_staff` = `is_admin_caller()` FOR ALL.
- **Multi-offering invariant (load-bearing):** a product can have MULTIPLE offerings in one week (Beets by the bunch AND the pound). So NO unique constraint on (week_starting, library_id); the add list must NOT dedupe/hide products already on the week — each "Add to market" creates its own row. Don't "fix" this by deduping.
- Files: page `src/pages/admin/market/index.astro`, API `src/pages/api/admin/market/save.ts` (ops add/update/remove, requireAdmin + isSameOriginPost, 303 flash redirects). Built by mirroring `admin/flex-inventory.astro` + `flex-inventory/save.ts` (the canonical weekly-editor pattern) and `admin/products/index.astro` (instant client search + library-first photo).
- Week helpers come from `lib/flex-order.ts` (`upcomingMondayET`, `addWeeksYMD`, `prettyWeek`, `isYMD`, `dollarsToCents`, `centsToDollars`, `formatCents`, `categoryEmoji`) — NOT lib/cycle, despite specs sometimes naming cycle.
- Nav: AdminShell `Market list 🛒` at `/admin/market`, right after `Market checkout 💳` (distinct: this is the product/price list; checkout is the flex-spend POS). Prefix-match safe — `/admin/market-checkout` doesn't start with `/admin/market/`.

**GOTCHA — missing migration:** when this was built, NO `market_offerings` migration existed in `supabase/migrations/` (table was applied live only). `database.types.ts` is HAND-MAINTAINED (see [[csa-portal-build-gotchas]]) so the type also had to be added by hand. I added idempotent migration `0054_market_offerings.sql` to version-control the existing table. If editing this feature, confirm the live schema matches the migration (esp. library_id NOT NULL + no unique on (week_starting, library_id)). NOTE: `supabase/migrations/` lives at the REPO ROOT, not inside `apps/csa-portal/`.

**PER-MARKET TAGGING (added 2026-06-22):** each offering is now tagged to a SPECIFIC market with a planned qty. New `market_offerings` columns (applied live by PM; version-controlled in idempotent `0055_market_offerings_tagging.sql`): `market_location_id uuid → pickup_locations`, `planned_qty`/`leftover_qty`/`donated_qty` numeric nullable. database.types.ts hand-updated to match.
- **The 4 markets** = `pickup_locations` where `is_delivery_zone = false AND day_of_week IN ('Tue','Sat','Sun')`: Lawrenceville (Tue), Bloomfield (Sat), Sewickley (Sat), South Side (Sun). Order Tue→Sat→Sun then by name.
- **Pack-day mapping (load-bearing):** Tue market → MONDAY pack; Sat/Sun market → THURSDAY pack. Helper `packDayLabel(day)` in the editor; `marketTabFor(day)` in harvest ('Tue'→'mon', 'Sat'|'Sun'→'thu', else null).
- Editor `add` op requires `market_location_id` (a `<select>` of the 4) + reads `planned_qty`; `update` op edits `planned_qty` too. `save.ts` validates `market_location_id` is one of the 4 via `isValidMarket()` (re-queries pickup_locations with the same filter — never trust the client). New error codes: `invalid_qty`, `invalid_market`. Blank planned_qty → null (free-typed numeric, negatives rejected).
- Editor offering list is GROUPED BY MARKET (subheading + pack-day chip); untagged legacy rows fall into an "Untagged" group at the end (still editable). If 0 markets configured, add form is disabled + a danger banner shows.
- **Harvest market section** (`/admin/harvest/[week]`, see [[csa-unified-harvest-doc]]) now SPLITS by day tab via market day: 'mon' tab → Tue markets only; 'thu' tab → Sat+Sun markets. Grouped by market, shows planned_qty + unit (— if null). Join `market_offerings → pickup_locations(id,name,day_of_week) → product_library`. `formatCents` import dropped from harvest (price no longer shown there).

Out of scope v1: price-list printing (roadmap #4) — DONE separately (the 🖨 Print price list action exists). leftover_qty/donated_qty columns exist but no reconciliation UI yet.

**WORKFLOW REBUILD (2026-07-06, Todd's brief: "checking items off, repeat last week, change on the fly").** `/admin/market/index.astro` was FULLY REWRITTEN from the old one-at-a-time per-product add forms + list/plan-grid tab views into a per-`(week, market)` editor. The old `save.ts` (ops add/update/remove/bulk-plan) is now UNREFERENCED dead code (left in place, safe). New endpoints under `api/admin/market/`:
- `bulk-add.ts` (form→303): array of REPEATED `library_ids` form entries + `week_starting` + `market_location_id` → one offering row each. Skips products already on (week, market); seeds new rows with the product's LAST-KNOWN unit+price (most recent offering any market), `planned_qty=null`. Powers both the "check off what we have" checklist AND the quick-add-single search.
- `copy-week.ts` (form→303): `week_starting` (target) + `market_location_id`. SOURCE week = `market_offerings WHERE market_location_id=… AND week_starting < target ORDER BY week_starting DESC LIMIT 1` (most recent PRIOR week WITH rows — NOT blindly 7 days back; a skipped week is skipped). Copies library_id/name/unit/price_cents/planned_qty/is_active/sort_order; SKIPS library_ids already on target (never dup, never overwrite edits). Does NOT copy leftover_qty/donated_qty (past-week reconciliation only).
- `update-row.ts` (JSON, optimistic): `{ id, planned_qty?, unit?, price_dollars?, is_active? }` — send only changed fields; `patch` MUST be typed `Database[...]['market_offerings']['Update']` (NOT `Record<string,unknown>` — that throws ts(2345); the old sign-edit.ts still has that pre-existing baseline error). Powers inline tap-a-number editing (revert-on-failure, mirrors pick-pack `/mark`).
- `delete-row.ts` (JSON): `{ id }` hard delete → styled two-tap inline confirm (no native confirm/alert).

**Deliberate UX shift from the multi-offering invariant:** the new "Add from products" checklist shows already-present products (per library_id, for the selected market) as CHECKED+DISABLED, and bulk-add/copy-week SKIP dups. This is a per-Todd simplification AWAY from the old "add the same product twice (bunch AND pound)" bulk flow. The DB model is UNCHANGED (no unique constraint added; existing multi-offering rows still display + are inline-editable/removable) — only the new bulk UX is one-per-product. There is no in-UI path to create a 2nd offering of the same product at the same market in v1 (flagged; edit unit on the existing row instead). Default market = "next-up" from ET today via `WEEKDAY_INDEX` delta; `?market=<uuid>` overrides. Consumers (price-list, pick-pack ×2) read across ALL markets and are unaffected by the editor's per-market filter.
