CSA "sync reliability" (built 2026-05-24 on csa-migration, gap-analysis P0-2 + P0-3). The 15-min Shopify→Supabase sync (`src/pages/api/sync/shopify-orders.ts`) issues REAL store credit + referral payouts; nothing watched it, and silent failure caused the original ~100-customer data gap. This work makes failure loud + visible. See also [[csa-flex-feature]], [[csa-referral-feature]].

**Error alert lives IN the sync endpoint (`sendSyncErrorAlert`), not a separate cron.**
- Fires at the END of a LIVE run when `errors.length > 0` (call-site guard `if (!dryRun && errors.length > 0)`). `errors[]` already aggregates BOTH thrown per-order failures (which also stamp `shopify_order_sync.last_error`) AND non-fatal referral/watermark issues — so it's the complete "touched a problem" signal; no need to separately re-query `last_error`.
- FAIL-SOFT: whole function in try/catch, returns early if `errors.length===0` (no spam on healthy runs) and if `!RESEND_API_KEY || !RESEND_FROM_EMAIL` (both are `optional()` env → `string|undefined`, MUST guard). A Resend failure logs + swallows; never throws (the run + watermark advance already completed before the alert). Reuses the EXACT Resend REST pattern from `src/pages/api/account/household.ts` (POST api.resend.com/emails, Bearer key, from/to/subject/text/html). Recipient hardcoded `todd@tinyseedfarmpgh.com`. Subject `⚠️ CSA sync: N order(s) errored on <date>`. Has its own inline `escapeHtml`.
- **How to apply:** any new in-endpoint best-effort email should copy this guard order (errors-only → config-present → try/catch → non-2xx logs). PM is separately wiring a DAILY HEARTBEAT pg_cron for the "didn't run at all" case — this in-app alert only covers "ran but errored."

**`/admin/sync` (`src/pages/admin/sync.astro`) is read-only, cookie-aware RLS client (`Astro.locals.supabase`), NOT service-role.** All four tables (`shopify_sync_state`, `shopify_order_sync`, `flex_transactions`, `referrals`) have `is_admin_caller()` admin-bypass RLS (migrations 0017/0022/0024), so the admin SELECTs every row. Middleware already gates `/admin/*` (303→/login unauth, →/dashboard?error=admin_only non-admin) — admin pages do NOT re-check auth. STALE threshold = 30 min (sync runs every 15 → 2 missed runs). Sections: last run (`last_synced_at` "X min ago" + red STALE Card tone='danger'), throughput (24h/7d counts from `processed_at` + 7d flex/referral $), needs-attention (`last_error IS NOT NULL` rows), money activity (flex_transactions + referrals last 7d). Uses AdminShell + Card + Table components (Table takes `columns[{key,label,align?,srOnly?}]` + `empty/emptyTitle/emptyIcon/emptyMessage` + `<Fragment slot="body">`). Added "Sync" nav tab (icon 🔄) to AdminShell + a "Sync health" link Card to admin/index.astro.

**Watermark/idempotency model (documented in `docs/CSA_SYNC_RUNBOOK.md`):** `shopify_sync_state.last_synced_at` advances to max(order.updated_at) ONLY at end of a completed run. Idempotency is the per-order `shopify_order_sync` ledger (presence = skip), NOT the watermark — and as of 2026-05-24 the credit is ADDITIVE (`issueStoreCreditDelta`, no balance self-guard), so the per-order ledger is the SOLE guard (runbook §3.2 updated; see [[csa-flex-feature]] / [[csa-referral-feature]]). **DUPE CAVEAT:** resetting the watermark backwards is safe ONLY because ledger rows cause a skip — if you reset the watermark AND truncate the ledger, the sync RE-ISSUES store credit + RE-PAYS referrals for the whole window (even more true now that credit is additive). Runbook also covers the `csa-shopify-sync` pg_cron job (`*/15 * * * *`, pg_net POST + Bearer CRON_SECRET), verify via `cron.job` / `cron.job_run_details` / `net._http_response`, recreate via `cron.schedule` reading CRON_SECRET from Vault (NEVER commit the secret), and `?dry_run=1` (all reads, zero writes, returns `planned[]`). PM has wired a `csa-shopify-sync-daily-fallback` pg_cron heartbeat (the "didn't run at all" backstop).

**LIVE-portal uptime monitor `.github/workflows/csa-portal-uptime.yml` (built 2026-05-24, commit 3ae4622, gap P0).** Cron `*/15` + push-on-self + workflow_dispatch. curls https://csa.tinyseedfarm.com: `GET /`→200, `GET /login`→200, `GET /api/sync/shopify-orders` WITHOUT auth →401 (one response proves the money-path API is BOTH up AND still protected — a 200 = auth-gate regression, a 5xx = endpoint down). Fails the job on any unexpected status (surfaces in Actions + GitHub workflow-failure notifications). curl + bash only, `--retry` to absorb blips, NO secrets. Fills the gap: `csa-portal-ci.yml` only tests the BUILT site (Playwright vs local dev), and the legacy `site-health-monitor.yml` targets the OLD Apps Script app at app.tinyseedfarm.com — neither watched the live Vercel portal. **How to apply:** the "401 without auth" probe is the cheap way to monitor a protected endpoint's uptime AND its auth gate in one check.

**Test coverage:** added `/admin` + `/admin/sync` to the `@unauth` PROTECTED_ROUTES in `tests/e2e/logged-out.spec.ts` → asserts 303→/login with ?next=. Full E2E now 37 (was 35).
