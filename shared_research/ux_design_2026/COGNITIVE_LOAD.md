# Cognitive Load - Reducing Mental Burden

## What Is Cognitive Load?

The total amount of mental effort being used in working memory. When cognitive load is too high, users:
- Make mistakes
- Abandon tasks
- Feel frustrated
- Don't return

---

## The 3 Types of Cognitive Load

### 1. Intrinsic Load
The inherent complexity of the task itself.
- **Can't eliminate** - but can sequence and scaffold
- Example: Filing taxes is complex; break into steps

### 2. Extraneous Load
Load created by poor design.
- **CAN and MUST eliminate**
- Example: Confusing navigation, unclear labels, visual clutter

### 3. Germane Load
Load devoted to learning and creating mental models.
- **Good load** - help users build understanding
- Example: Onboarding that teaches the system

---

## Key Research: Miller's Law

**"The average person can hold 5-9 items in working memory"**

### Implications:
- Navigation: 5 items max (ideally 3-4)
- Form fields visible at once: 5-7 max
- Choices in a dropdown: 7 max before grouping
- Steps in a process: 5 max visible

---

## Key Research: Hick's Law

**"Decision time increases logarithmically with the number of choices"**

### Implications:
- More options = slower decisions = higher abandonment
- Reduce choices to essentials
- Use smart defaults to eliminate decisions
- Group related options

---

## Cognitive Load Audit Checklist

### Navigation
- [ ] 5 or fewer primary navigation items?
- [ ] Clear, descriptive labels (not clever)?
- [ ] Current location always visible?
- [ ] One-click access to key functions?

### Visual Design
- [ ] Clear visual hierarchy?
- [ ] Adequate whitespace?
- [ ] Consistent patterns throughout?
- [ ] No decorative clutter?

### Content
- [ ] Scannable headings?
- [ ] Short paragraphs?
- [ ] Bullet points for lists?
- [ ] Plain language (no jargon)?

### Interactions
- [ ] Clear feedback for every action?
- [ ] Undo available for destructive actions?
- [ ] Autosave to prevent data loss?
- [ ] Smart defaults to reduce decisions?

### Forms
- [ ] Only essential fields visible?
- [ ] Inline validation?
- [ ] Clear error messages?
- [ ] Progress indicator for long forms?

## Reduction Strategies

### 1. Chunking
Break complex information into digestible pieces.
```
Bad:  1234567890
Good: 123-456-7890
```

### 2. Recognition Over Recall
Show options instead of requiring memory.
```
Bad:  "Enter command"
Good: [Button] [Button] [Button]
```

### 3. Visual Hierarchy
Use size, color, and position to signal importance.
```
Primary action:   Large, colored button
Secondary action: Smaller, outlined button
Tertiary action:  Text link
```

### 4. Consistency
Same patterns everywhere reduce learning load.
```
If "Save" is top-right on one screen,
it should be top-right on ALL screens.
```

### 5. Progressive Disclosure
Hide complexity until needed.
```
Show: 3 essential fields
Hide: 10 optional fields behind "More options"
```

---

## Warning Signs of High Cognitive Load

1. **Feature sprawl** - Too many things visible at once
2. **Decision paralysis** - Users don't know where to start
3. **Error rates** - Users making frequent mistakes
4. **Abandonment** - Users leaving mid-task
5. **Support requests** - "How do I...?" questions

---

## Measurement

### Quantitative:
- Task completion time
- Error rate
- Abandonment rate
- Time to first action

### Qualitative:
- User testing observations
- "Think aloud" protocols
- Post-task difficulty ratings (NASA-TLX)
- Support ticket themes
